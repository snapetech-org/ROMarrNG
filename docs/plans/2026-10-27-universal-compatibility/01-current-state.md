# Evidence and requirement traceability

All source observations below refer to `bd06296a776ffa0ffcfdcd31f051e3f92fd6f07c`. Function names are the durable navigation anchors; line numbers will move. “Reproduced” means an isolated local probe, not a production reproduction. No claim is made about the reporter's version, configuration or actual ROM files.

## What the code currently does

| ID | Evidence | Confidence and consequence |
| --- | --- | --- |
| E01 | [`libraries.py`](../../../romarr/libraries.py), `FolderConfig` has only `root`; `FolderLibrary.games()` uses the first relative path component and emits an empty platform for files directly in the root. It does not set `platform_slug` or `cover`. | **High, reproduced:** `/PS1/Example.chd` scanned with `/PS1` as root and `/PS2/Example.iso` with `/PS2` as root both have blank platform and cover. `/multi/psx/Another.chd` has display platform `psx` but blank slug. This exactly fits a plausible reported setup. |
| E02 | [`app.py`](../../../romarr/app.py), `_refresh_counts()` aggregates backend `Game` rows; `_publish_library()` groups by display platform; `library_view()` filters display names. `source` carries a display library label only for multiple libraries. Its `source` filter is provenance such as Archive/Flashpoint, not a library ID. | **High, source:** aliases cannot reliably coalesce across backends, library identity is not a stable filter, and grouping cannot repair absent platform data. |
| E03 | [`metadata.py`](../../../romarr/metadata.py), `Metadata.identify()` provides a lookup; provider save in `app.py` calls `reload_metadata()` only. `/api/v1/metadata/lookup` returns a result without persisting a shelf overlay. | **High, source:** configuring a provider does not initiate inventory enrichment or fill folder-library covers. The current Games shelf mostly displays metadata supplied by the backend. |
| E04 | `metadata.py`, `_rawg()` requests one search result; `_igdb()` uses `limit 1`, without an explicit platform constraint. `GameInfo` has no provider entity ID. `matched_by=dat` describes the lookup term, not proof of the provider match. | **High, source:** blindly reusing this lookup at scale risks the wrong platform/edition. A good DAT identity still needs a validated provider mapping. |
| E05 | [`ui.py`](../../../romarr/ui.py), `RENDER.library` binds every tile to `shelfEditor()`, whose actions edit status/rating/notes through `/api/v1/game/meta`. | **High, source:** the limited click behavior is implemented, rather than an operator failing to find a hidden detail action. |
| E06 | `app.py`, `_present_titles()` reads the configured platform directory when available; otherwise it calls `library_view()` with its default 120-item page, without a platform filter. Imported verification is inferred from the bounded event log by lowercased title. | **High, source:** server-only or differently laid-out libraries can produce incomplete/cross-system presence answers. History cannot be the durable verification database. |
| E07 | `app.py`, `collection_plan()` falls back to the first DAT if an explicit DAT name is not found; an empty platform can propagate to the batch. | **High, source:** invalid selection can silently change the set; a preview can lead to requests with an unresolved platform. Require exact selection and a validated system binding. |
| E08 | `app.py`, `collection_step()` ignores the dictionary returned by `request()` and calls `batch.record(name, ok=True)` unless an exception is raised. | **High, reproduced:** a stub returning `{"ok": false, "error": "No usable release was found."}` produces `status=done`, `done=1`, `failed=0`. Even successful dispatch would not prove import completion. |
| E09 | `ui.py`, `RENDER.collections` offers “Run next”; `collection_start()` persists a queue, while the existing scheduler does not own its normal draining. The preview renders only its first 300 titles. | **High, source:** work is manually stepped and the display is not a complete selectable catalog. Preserve old controls while moving execution behind a resumable worker. |
| E10 | `app.py`, `request()` and platform-qualified `candidates()` already share `_search_releases()`. Interactive results include rejections and manual grabs. Add New preselects a platform; Interactive Search starts with Any platform. The no-platform search branch does not enumerate direct indexers like `_search_releases()` does. | **High, source; reporter-specific cause unknown:** different context and automatic acceptance can explain visible matches with no automatic pick. Do not claim there are wholly unrelated search engines or fix this by dropping scoring protections. |
| E11 | [`clients.py`](../../../romarr/clients.py), `QbitConfig` has username/password only. [`downloaders.py`](../../../romarr/downloaders.py), `CLIENT_TYPES` and `build_client()` expose/pass those fields only. The session already handles 200 `Ok.`, 204 and a bounded auth retry. | **High, source:** add a real API-key path without regressing session compatibility. Official newer qBittorrent API-key support is documented in [compatibility sources](04-compatibility.md#primary-sources). |
| E12 | [`lists.py`](../../../romarr/lists.py) parses/fetches lists; `app.py:list_sync()` adds resolved entries directly to Wanted and uses a per-list title/platform ledger. | **High, source:** a catalog cannot be introduced as an ordinary automatically synced import list without adding review/intent semantics. |
| E13 | [`dat_catalog.py`](../../../romarr/dat_catalog.py) already provides opaque `dat-<sha256>` identities, platform mapping, browse/search/detail and policy selection. `metadata.py` has IGDB catalog functions and filters for SeerrNG. [`frontends.py`](../../../romarr/frontends.py) already exports several frontend formats. | **High, source:** reuse these foundations; do not fork the DAT key algorithm, duplicate provider clients, or promise DATs supply genre/art. Catalog coverage and provider crosswalks still need new work. |
| E14 | [`store.py`](../../../romarr/store.py) atomically replaces a JSON snapshot under an RLock. Events are capped at 2,000; saved queue at 500. `save()` logs an OSError rather than propagating a durable-write failure. Personal metadata keys use platform/title. | **High, source:** a large catalog needs indexed storage; transactional job/outbox durability cannot be claimed by wrapping a mutator that silently fails to save. |
| E15 | Folder `count()` and each `games()` page walk the tree; `_walk` has 50,000 bounds. [PR #58](https://github.com/snapetech-org/ROMarrNG/pull/58), head `032f79eb0e32998b2b49c7046235d9134b913c0a` at inspection, proposes a 600-second snapshot cache. | **High for source/overlap:** reuse or reconcile that patch. Its reported production timings are author evidence, not measurements performed for this plan. Also test concurrent refresh, truncation and stale snapshots. |
| E16 | [`setup-experience-contract.md`](../../design/setup-experience-contract.md) preserves a simple secure claim, existing settings and confirmed paths. [`playability.py`](../../../romarr/playability.py) already distinguishes actual file routes; [`openapi.py`](../../../romarr/openapi.py) documents the API. | **High, source:** extend these rather than introducing incompatible parallel setup, playback or API models. |
| E17 | `app.py`, `frontend_rows()` also calls `library_view()` without paging and falls back to constructing a path from the default library root, platform and name. `ops.make_backup()` currently describes a settings backup, not a complete inventory/job backup. | **High, source:** frontend exports need complete source-scoped inventory and real file locators; the new full-state backup must be versioned separately from the existing configuration-only format. |

## Reproduction and unresolved evidence

Use only synthetic filenames/bytes, fake providers and isolated configuration for baseline probes. The planning probes instantiated `FolderLibrary(FolderConfig(root=...))` for `PS1`, `PS2` and `multi/psx` trees, then invoked `collection_step()` on an isolated Store with `request()` stubbed to return failure. Exact observed values are recorded in E01/E08. Six existing test modules still passed (108 tests).

The user's precise Collections symptom, release-search failure, provider health and deployment/version remain **unknown**. `R00` turns each into a reproducible integration scenario; diagnostic work must not request real credentials, private tracker URLs or ROM uploads. An optional redacted support report can capture version, backend kind, platform mappings, scan counters and error codes. Issue [#59](https://github.com/snapetech-org/ROMarrNG/issues/59) separately reports confusing Browser/Playwright setup on Unraid; `R14` addresses discoverability and compatibility diagnostics without making browser acquisition a prerequisite.
